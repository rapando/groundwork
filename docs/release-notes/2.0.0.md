groundwork 2.0 stops writing your infrastructure code for you. Setting up a new repository now asks which tools it uses (Terraform or OpenTofu, Ansible, or both) and writes only what groundwork needs for them: its own config, and with both, the inventory script that turns your Terraform hosts into Ansible hosts. You write the Terraform, for any provider, and the playbooks.

## What's breaking

- **`groundwork init` in an empty repository** no longer writes Terraform, roles, playbooks, static inventories, pre-commit or CI files. `--preset` and the provider, state backend and region flags are removed. Scripts that pass them fail with an unknown-flag error.
- **The Go module path is now `github.com/rapando/groundwork/v2`.** Install from source with `go install github.com/rapando/groundwork/v2/cmd/groundwork@latest`. The install script and release archives are unchanged.

`groundwork.yaml` is unchanged: existing projects open as before, and nothing set up by 1.x is touched.

## Upgrading from 1.x

```sh
curl -fsSL https://raw.githubusercontent.com/rapando/groundwork/main/install.sh | sh
groundwork service restart
```

## What's new

### Setting up a new repository
- **Choose your tools**, with `--tools` on the command line or the Tools step in the console. Terraform alone writes `groundwork.yaml` only. Ansible alone adds `ansible/ansible.cfg`. Both add `ansible/inventory/tf_outputs.py`, which reads an `ansible_hosts` output from your Terraform. Environments, layout and checks only appear for the tools you chose.
- **The ansible-vault password is set during setup.** Type it in the console, where it's kept in memory and unlocks the vault straight away. Or name a password file outside the repository and groundwork creates it with mode 600, or uses it if it already exists. When setup is done, **Add a secret** opens Variables → Secrets → New secret.

### OpenTofu
- Setup and detection write `terraform.binary: tofu` when only OpenTofu is installed, and the console offers it as a choice.
- The inventory script runs the binary you chose, or whichever of `terraform` and `tofu` is installed. `GROUNDWORK_TF_BINARY` overrides it.

### Installing tools
- Install hints use an installer found on your machine: Homebrew, pipx, uv or `go install`. The others are listed under **Other ways to install**. The same hints appear in `groundwork doctor`, check results and errors. pipx is no longer assumed.

### Smaller changes
- Checks skip a Terraform root that `groundwork.yaml` names but that doesn't exist yet, instead of failing.
- The `.tflint.hcl` offered on the Detect screen no longer enables the AWS ruleset.
