groundwork 1.0 is a local web console for Terraform and Ansible: one service on your machine that hosts every infrastructure repository you work on, checks it as you edit, shows plans you review and approve before anything is applied, and explains what went wrong when something does.

## What 1.0 promises

The surfaces that are stable from here on, and what a change to each one means for the version number, are written down in [docs/compatibility.md](https://github.com/rapando/groundwork/blob/main/docs/compatibility.md). In short: `groundwork.yaml` and the CLI only change in a compatible way until a 2.0; a project's `.groundwork/` and the service's data directory are migrated forward (never down) with a backup first; the HTTP API is private to the bundled UI.

## Upgrading from 0.x

```sh
curl -fsSL https://raw.githubusercontent.com/rapando/groundwork/main/install.sh | sh
groundwork service restart
```

Every project's `state.db` is checked and copied to `state.db.bak-<schema>` before it is migrated, the first time the project is opened by 1.0. `groundwork.yaml` needs no changes. If you installed before 0.2 and still start groundwork in a terminal, see [upgrading to 0.2](https://github.com/rapando/groundwork/blob/main/docs/install.md#from-01-to-02) first.

Releases are now signed: `install.sh` verifies `checksums.txt` with cosign when it is installed, and each archive has an SBOM.

## Since 0.4

- The session token never reaches the service log or `server.json`.
- `groundwork.yaml` is validated like request input: vault password files that would be executed, workspace and environment names, the drift webhook and ignore patterns.
- Linter findings, stage errors and `git diff` are redacted; values of variables declared `sensitive` are masked wherever a tool echoes them.
- A failed plan leaves no plan file behind; `.groundwork/` is private to your user.
- One service per data directory is enforced with a lock; a busy port is an error that names the owner, never a silent move to another port.
- A panic in one project's background work no longer takes the service down: it is recovered, logged with its stack and shown as an issue on that project.
- Runs have a timeout (`run_timeout`, default 2 hours); after a hard stop groundwork reports tools it left running.
- The service log is rotated and `groundwork service logs -f` tails it; `service status` shows version, uptime, port, projects and running jobs; `GROUNDWORK_LOG=debug` and `--log-format json`.
- Doctor warns when terraform, tofu or ansible is older than the supported floor (1.4, 1.6, 2.14).
- The UI shows when it is reconnecting, its dialogs trap focus, the file tree and problem tabs take arrow keys, and every screen passes an accessibility scan.

## Known limitations

- macOS and Linux only (amd64 and arm64).
- Locks are in-process: a `terraform` you run in your own terminal is not coordinated with the service.
- The HTTP API is not a public surface; scripts should use the CLI (`groundwork check --json`, `groundwork doctor --json`, `groundwork projects`).
- No Homebrew tap yet; the install script or `go install` are the ways in.
